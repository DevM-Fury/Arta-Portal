Validated Remediations

RESOLVED Anonymous role administration remains blocked

Unauthenticated POST /api/role/create_role.php still returns 401 Authentication required. The endpoint remains protected by role-based session checks and now also expects a CSRF token for authenticated browser requests.

RESOLVED Anonymous assignment user enumeration remains blocked

Unauthenticated GET /api/assignment/get_users.php?type=office&id=1 still returns 401 Authentication required. The previous user-directory exposure was not reproducible.

RESOLVED Password recovery behavior remains hardened

Forgot-password still returns a generic success response for unknown accounts and uses reset links instead of direct password replacement. Registration POST now also requires a valid CSRF token and reaches normal field validation when the token is supplied.

RESOLVED CSRF protection is now enforced on the affected browser write actions

The shared API guard now issues and validates session-backed CSRF tokens. The role-management and system-assignment pages were updated to send X-CSRF-Token headers on JSON POST requests, with retry-on-expiry handling. Registration was also updated to submit with a CSRF token.

RESOLVED Raw backend exception leakage was removed from the retested API sweep

A follow-up source sweep for display_errors = 1, wildcard CORS on exposed APIs, error_details, and direct $e->getMessage() responses in the API tree returned no matches after remediation. The previously leaking registration, lookup, assignment, systems, and list endpoints now return generic client-facing errors.

RESOLVED Anonymous full organization metadata exposure was reduced to controlled lookup mode

The office, division, unit, and designation endpoints now require authentication for the full dataset. Anonymous callers only receive the minimal registration lookup dataset when lookup=1 is explicitly used. Validation showed 401 for anonymous full office access and 200 for anonymous lookup=1 requests returning minimal records.
